# 00 · 愿景

> 建立：2026-11-21
> 一句话：**把「一个标注点」升级成「一条能自证效果的闭环」。**

---

## 1. 为什么要做这件事

### 1.1 现状：被工具化的一个点

过去两年我的工作是：

- 读评测集、归类场景、分析 badcase、做补强集
- 在**单节点**上把一个领域基模的某类能力往上推

这类工作有真实价值，但它有三个天花板：

| 天花板 | 表现 |
|---|---|
| **边际收益递减** | 通用模型能力曲线抬得太快，领域强化的相对优势在缩水 |
| **不可归因** | 能力涨了，但说不清是数据、训练还是评测的功劳 |
| **不可交付** | 我是链路中间的一环，交付物是「一个更好的模型」，不是「一个能跑的系统」 |

### 1.2 判断：价值正在从「点」迁移到「线」

> 这不是「后训练没用」，而是：**后训练的价值必须由端到端系统来兑现。**

大模型是「给啥出啥」。指望只做后训练的人搞出涌现级能力，是错配期望。
真正稀缺的是：

1. 把业务拆成**可评测**的节点
2. 让每个节点**选对模型**（大的 / 小的 / 规则的）
3. 让整条线在**成本、延迟、质量**三个约束下**稳定运行**
4. 出了问题时能**定位到是哪一层**坏了

这四件事，只有做过完整一条线的人才答得上来。

### 1.3 所以：用一个真实场景，竖着走一遍

场景选**客服工单**，理由：

- 我有领域直觉（做过客服增训项目），不用花时间理解业务
- 天然有明确的对错（分类对不对、回复能不能用）
- 天然有成本压力（量大、单价敏感）→ 小模型有生存空间
- 天然有运营问题（峰值、新舆情）→ 能长出真问题

## 2. 三个必须回答的问题

这个项目不是「做一个客服机器人」，是**用客服当试验台，回答三个问题**。

### Q1 · 什么叫「做对了」？

> 没有 eval 的项目，在面试里等于没做。

- 分诊：宏 F1、混淆矩阵、**置信度校准（ECE）**
- 回复：rubric 打分 + 人工抽检 + LLM judge 校准
- 系统：每千单成本、P95 延迟、失败模式分布

产出：`docs/03-eval-design.md` + 可复现的 `run_eval.py`

### Q2 · 小模型到底值不值？

- 0.6B + LoRA 能做到 macro-F1 多少？
- 和「大模型 API + few-shot」比，质量差多少、成本差多少、延迟差多少？
- 量化（int8/int4）之后掉多少？
- **在什么置信度阈值下，路由到小模型是划算的？**

产出：一张「质量 × 成本 × 延迟」的三维对比表，以及一条路由阈值曲线

### Q3 · 峰值和新舆情来了，系统怎么不崩？

- 峰值：QPS 涨 5 倍，是排队、降级还是切大模型？
- 漂移：新类别出现时，怎么在**没有标注**的情况下发现？
- 兜底：什么时候必须交给人？交出去的比例和成本是多少？

> 这两个问题在本机没有最终答案 —— 但**不做项目，你连问题都问不出来**。
> 拿到公司数据后回来补答案，见 `docs/05-open-questions.md`。

## 3. 成功标准（可验收）

一个陌生人 clone 这个仓库，应该能在 30 分钟内：

- [ ] 跑通 baseline eval，看到分数
- [ ] 看懂架构图，说清每一层在干什么
- [ ] 看懂一张「小模型 vs 大模型」的对比表，并理解取舍
- [ ] 看懂一次压测报告和一次漂移演练

以及我自己能：

- [ ] 3 分钟内讲完这个项目：问题 → 方案 → 数字 → 取舍 → 反思
- [ ] 被追问 3 层不崩（为什么 0.6B？为什么这个阈值？为什么这样切数据？）

## 4. 与既有文档的关系

`../AI职业发展_三支柱计划.md` 里的 SOP Agent 是**目标形态**（12 周、6 模块）。
本仓库是它的**最小可运行内核**：先把一条窄线跑通、跑出数字，再往上长模块。

优先级：**能跑 > 能讲 > 完备**。

## 5. 不做清单（战略就是选择不做什么）

| 不做 | 为什么 |
|---|---|
| 通用 Agent 平台 | L1 认知层正在被模型吃掉，且我没有生态优势 |
| 多轮对话 / 记忆 | 单轮分诊 + 单轮回复已足够验证全链路 |
| 前端框架 | CLI + 单页足够；前端不是我要证明的能力 |
| 多机多卡 | 6GB 单卡是刻意保留的约束，用来练估算 |
| 追 SOTA | 要证明的是流程与取舍，不是榜单排名 |
| 自建向量库 | 用现成的；除非它能回答一个新的问题 |

## 6. 风险

| 风险 | 对策 |
|---|---|
| 摊子铺太大，三周后烂尾 | 每阶段必须有可演示产出，否则砍范围 |
| 没有真实数据，做完是玩具 | 数据适配器隔离，合成数据只验证链路；真数据到位只换 adapter |
| 只写文档不写代码 | 每阶段至少 20 个 commit；文档只在阶段末写 |
| 变成「又一个大模型套壳」 | 必须有 eval 数字和成本对比，否则不算完成 |
| 公司数据不能带出 | `data/private/` 永不入库；只带**结论和参数**，不带样本 |
