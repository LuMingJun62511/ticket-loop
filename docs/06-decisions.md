# 06 · 决策记录（ADR）

> 格式：背景 → 选项 → 决定 → 代价 → 什么时候会反悔。
> 面试里被追问「为什么」时，答案都在这里。

---

## ADR-001 · 做竖切，不做补点

- **背景**：现有经验集中在单节点模型能力（L0）与 RAG 基建（L2.5），缺端到端。
- **选项**：A 继续深耕 L0 评测/后训练；B 再补一层 RAG；C 竖着打通一条线。
- **决定**：C。
- **代价**：每一层都做不到最深；短期没有「某层专家」的标签。
- **何时反悔**：如果发现某层是明显瓶颈（例如路由效果怎么调都上不去），再横向深挖那一层。

---

## ADR-002 · eval 先行，且不绑定实现

- **背景**：最常见的失败是先写功能，最后补评测，结果指标不可比。
- **选项**：A 先做模型，再补评测；B 先做评测骨架，模型后接。
- **决定**：B。`run(model: Callable, goldens)` 的签名先定死。
- **代价**：第一晚看不到「AI 效果」，只有空壳。
- **何时反悔**：不会。这是本项目的地基。

## ADR-003 · 0.6B + LoRA，不全参、不追大模型

- **背景**：本机 6 GB 显存；任务只有 2–3 类。
- **选项**：A 全参微调 0.6B；B LoRA 0.6B；C 直接调 API。
- **决定**：B 为主，C 作为对照臂。
- **理由**：
  - 全参 fp16 需要 > 8 GB，本机不可行（见 `04-compute-budget.md`）
  - 分类任务 + 2–3 类，0.6B 容量足够，瓶颈在数据不在参数
  - 有对照臂才能回答「小模型值不值」
- **代价**：LoRA 的效果上限低于全参；结论不能外推到更大模型。
- **何时反悔**：如果 0.6B 的 F1 比 API few-shot 低超过 10 个点，说明容量或数据不够，考虑 1.7B（需租卡）。

## ADR-004 · 数据适配器隔离，合成先行

- **背景**：公司数据不能带出，但项目不能等数据。
- **选项**：A 等真数据；B 用公开数据硬做；C 合成数据跑通 + adapter 隔离。
- **决定**：C。
- **做法**：`data/{synthetic,private}/` 同一 schema，`load_raw` 只认路径。
- **代价**：合成数据分布太干净，指标会虚高，必须主动注入噪声。
- **何时反悔**：真数据到位后，用同一套 eval 重跑，**预期指标会掉**，这是好事。

---

## ADR-005 · CLI + 单页，不做前端

- **背景**：要证明的是链路和取舍，不是 UI 能力。
- **决定**：CLI 打底，最多加一个 Streamlit 单页做 demo。
- **代价**：demo 不够「惊艳」。
- **何时反悔**：如果要给非技术人演示，再加最薄的一层页面。

---

## ADR-006 · Windows + uv，不用 make

- **背景**：本机 Windows，`make` 不存在；Python 3.9 偏旧。
- **决定**：uv 管环境与 Python 3.11；任务入口用 `scripts/*.py`。
- **代价**：和 Linux 生态的命令习惯略有差异。
- **何时反悔**：如果后续要上 CI/容器，再补 `Makefile` 或 `justfile`。

---

## ADR-007 · 不用 LangChain / LlamaIndex

- **背景**：这类框架会遮住每一层的输入输出。
- **决定**：手写最小的 `Endpoint` / `router` / `trace`。
- **代价**：前期多写一些胶水代码。
- **何时反悔**：如果要接大量工具/多 Agent 协作，再考虑 LangGraph。
