# 05 · 只有公司数据能回答的问题

> 这些问题的价值不在答案，而在**问题本身**：
> 不做这套系统，你根本不知道该问什么；带着结构化问题回去找人，比「我想看看数据」有效十倍。
>
> 原则：**只带问题走，不带样本走。** 回来的是结论和参数，不是数据。

---

## 1. 负载与峰值

| # | 问题 | 为什么问 | 拿到后影响 |
|---|---|---|---|
| Q1 | 日均工单量？峰值/均值比？峰值出现在什么时段？ | 决定压测的并发档位 | P3 压测参数 |
| Q2 | 单工单平均字数 / P95 字数？ | 决定 seq_len 和 KV 预算 | P2 训练配置、P3 batch |
| Q3 | 峰值持续多久（分钟级/小时级）？ | 决定排队 vs 扩容 vs 降级 | P4 降级策略 |
| Q4 | 现有的首响 SLA 是多少？ | 决定延迟目标是否现实 | README 指标表 |

## 6. 回填方式

每拿到一个答案：

1. 在这里打勾，写「结论」一列
2. 如果它改变了设计，写一条 ADR（`docs/06-decisions.md`）
3. 在 README 指标表里更新对应目标

> 这张表本身就是作品集的一部分：
> 它证明你能**把模糊的业务问题，翻译成可测量的工程约束**。
